# M0.1 — Host setup

## Setup
- Host: Ubuntu 26.04, x86_64, 32 threads, 30 GiB RAM, ext4 `/` 289G free
- Target: Pi 5, Debian 13 trixie, kernel 6.18, glibc 2.41
- Links: Ethernet (`ssh pi5`, key-based) ; UART pending (no adapter yet)
- Repo source of truth = host; Pi does `git pull`
- Bootstrap: `scripts/host-setup.sh` (idempotent, verified by 2nd run = no-op)

## Pi audit
- SD: p1 = /boot/firmware (FAT, kernel+DTB+config), p2 = / rootfs (ext4)
- 2 GiB zram swap (compressed RAM, protects SD)
- serial-getty on ttyAMA10 -> login on 3-pin debug UART

## ELF / cross-compile findings
- Native and cross `hello`: ELF64 AArch64 PIE, interpreter /lib/ld-linux-aarch64.so.1
- On x86 host: "Exec format error" — kernel binfmt_elf rejects e_machine AArch64 (ENOEXEC)
- Runs on Pi although host glibc 2.43 > Pi 2.41: binary needs max GLIBC_2.34
  - Rule: runs iff max(required symbol version) <= target glibc
  - Proper fix later (P2): build against Pi sysroot

## ccache
- 20G limit; flags are part of the hash (-O2 hit, -O0 miss)
- Kernel usage (P4): make CC="ccache aarch64-linux-gnu-gcc"
